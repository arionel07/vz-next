# Внешние интеграции и выпуск Next

Состояние после этапа 8. Живые платежи, учётные данные и рабочая база не использовались.

## Готово в Next

- Поиск подключает Meilisearch через существующий `SearchProvider`, если задан `MEILISEARCH_URL`; при пустом URL или сбое использует MySQL. Имя индекса по умолчанию — `vizaje_nica_products`, как в legacy. Meilisearch получает только поиск товаров; популярные запросы и запись истории остаются в MySQL.
- Каталог по-прежнему перепроверяет ID результатов поиска по данным MySQL и применяет действующие правила публичности, цены и изображений.
- Добавлены `/sitemap.xml` и `/robots.txt`. Sitemap содержит публичные RU/RO страницы и опубликованные записи каталога, брендов, новостей/блога, акций и подборок. Он исключает корзину, checkout, аккаунт, поиск и другие личные/служебные маршруты. При недоступной БД возвращается список статических публичных страниц.
- Известные языковые алиасы в RU/RO catch-all перенаправляются постоянным HTTP 308. Полной таблицы перенаправлений со старого домена пока нет.
- Google Tag Manager и Microsoft Clarity загружаются только при сохранённом согласии на аналитику; GTM дополнительно требует согласия на маркетинг. Без ID в окружении скрипты не загружаются.
- Серверные ошибки получают структурированную запись с типом ошибки, digest, методом и шаблоном маршрута; URL с query, заголовки и содержимое запроса не записываются.
- Создан совместимый `POST /api/subscription`: проверяет email, сохраняет подписчика в существующую таблицу и отправляет приветственное письмо через Resend, если Resend настроен. В legacy публичной формы в footer не было, поэтому endpoint пока не подключён к новой форме.
- Добавлен `.env.example`. Секреты в него не помещать.

## Внешние блокеры перед включением

### Paynet

Оплата картой остаётся выключенной. Перед подключением нужны sandbox merchant credentials, официальные URL/версии API, точные поля подписи и callback, правила повторного уведомления, тестовые сценарии отмены/ошибки и production callback URL. После этого проверить идемпотентность callback и сверку суммы с серверным заказом.

### WorkApp / 1С

В Next нет работающей синхронизации. Наблюдаемый legacy контракт сохранён как черновик в `../../../docs/workapp-1c-observed-contract.md`; перед реализацией нужны подтверждённая спецификация, HTTPS endpoint, способ авторизации, форматы ошибок, правила подтверждения/повтора заказов и официальные операции с бонусами. Не запускать обмен с production, пока эти ответы не получены.

### Meilisearch

Read-provider готов, но сам индекс и актуальность документов должны подтверждаться отдельно. В legacy есть индекс `vizaje_nica_products` и best-effort синхронизация при импорте каталога. Для окончательного перехода нужно настроить read-only key в Next, проверить доступ к индексу, сравнить выборку с MySQL и перенести/добавить задачу индексации для процесса, который останется после отключения legacy. Если проверка Meilisearch не проходит, Next продолжает поиск в MySQL.

### Email и подписки

Для рабочих писем нужны `RESEND_API_KEY` и `AUTH_EMAIL_FROM`; для SMS-кодов — `SMS_USERNAME`, `SMS_PASSWORD` и при необходимости `SMS_API_URL`/`SMS_FROM`. После настройки проверить доставляемость домена и письма восстановления/подтверждения. Подписка хранится в общей таблице `subscriptions`; она не имеет уникального ограничения на email, поэтому перед добавлением конкурентных или пакетных импортов проверить дубликаты и согласовать миграцию индекса. Сейчас endpoint повторяет поведение legacy и не реализует double opt-in или отписку.

## Выпуск и перенос данных

- `NEXT_PUBLIC_SITE_URL` должен быть production-origin без завершающего пути. Он используется для canonical base и sitemap.
- Перед переносом сделать резервные копии MySQL и файлов изображений, затем сверить таблицы, количество записей и выборочные связи. Существующая локальная копия SQL не подтверждает целостность production-копии.
- Получить полный список публичных legacy URL и утвердить таблицу 301/308 до переключения DNS. Сейчас постоянные перенаправления покрывают только известные алиасы локалей; исторические URL ещё не сопоставлены.
- После выбора production-origin добавить Search Console/Bing Webmaster Tools, проверить sitemap/robots и настроить мониторинг запросов. Текущая аналитика не загружается до согласия пользователя.
- `next.config.ts` уже использует `cacheComponents`. Перед запуском на VPS замерить MySQL и страницы с живыми данными, затем задать явные сроки кэширования для стабильных каталогов/контента и правила инвалидирования после импорта. Не кэшировать персональные ответы, корзину или checkout.
- Настроить ротацию логов, дисковое место, время/часовой пояс, TLS, резервные копии, восстановление и проверку здоровья процесса. Пример локального Compose с опубликованным MySQL портом не предназначен для production без отдельной сетевой и секретной конфигурации.

## Переменные окружения

См. `.env.example`. Для включения поиска достаточно `MEILISEARCH_URL`, индекса и search key. Не передавать административный ключ Meilisearch браузеру; задавать его в Next не требуется. Paynet и WorkApp переменные намеренно не добавлены до получения их официальных контрактов.
